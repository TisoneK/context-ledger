# Flaws Log (append-only — flows to the protocol package)

Friction caused by the `.context_ledger/` system or the protocol itself. See
`README.md` in this directory for the split between `flaws/` and
`inefficiencies/`.

Append-only, but compactable — the log never grows without bound:

- **Resolved entries move verbatim** to cold storage: once an entry is
  explicitly marked `RESOLVED` / `superseded` / fixed, cut it unchanged
  into `archive.md` in this directory so startup reads only the live
  entries. Age alone never makes an entry eligible — an unresolved flaw
  stays here as a live trap.
- **Repeats roll up:** when 3+ entries describe the same recurring
  protocol trap, append ONE consolidated `Recurring` entry — the pattern,
  how many times, the current workaround — and move the individual
  entries verbatim into `archive.md`. The live log keeps the pattern, not
  the repeats.

`ledger-mem prune` reports log sizes, archive-eligible entries (`--list`
names them), and roll-up candidates.

## 2026-10-31 — Exit/clock-out is the most-forgotten step, and the ledger does not enforce it (Soren, S021)

- **Flaw:** the Exit checklist — log the session entry, clear `tasks/current.md`, prune, regenerate STATE, **remove your roster row + `ledger-guard release`** — is the single most commonly forgotten step, for **every** agent, not just one, and the protocol relies on the agent *remembering* it. It is worst **after a resume / context compaction**: the agent loses the memory that it even has an open session to close (the intra-session decay the supervisor named — full protocol early, then only "fill the session entry + run the exit gate," then after resume no memory of the protocol at all). Unlike a commit (pre-commit hook) or a push (pre-push hook), "the session is ending" is not a git event, so there is no point-of-action gate to catch an agent that simply stops.
- **Symptom:** this session. I "paused" with my roster row still `Working`, **no S021 session entry logged at all**, and `tasks/current.md` still holding the prior session's (S020) stale task — the board would have shown a worker who had left, and the duty log would carry no record the session happened. The supervisor had to prompt it ("do i need to remind you to checkout of the repos??? this has been the most common flaw"). Kin: S011 re-check-in after a file was left untracked at close; S016/S017 stale-board collisions.
- **Root cause:** the enforcement model hangs off git events (commit/push), but exit is not a git event. The existing detection — `ledger-guard remind`/`sessions` flag a stale heartbeat, `ledger-mem check` warns when a session entry exists while the row still claims the office — is **warn-only and fires on the NEXT agent**, not the leaving one; the leaving agent is gone before anything nudges it.
- **Suggested fix:** enforce exit at the hooks the ledger *does* have, plus a resume-proof reminder and self-heal. (0, the key one for resume) The per-turn guard reminder (`ledger-guard remind`) already survives compaction and fires on the **first turn after a session resumes** — it should detect that *this* session has an open row (its `LEDGER_SESSION` / live heartbeat matches a `Working` roster row) and re-inject the open-session obligation + the exit checklist, so a resumed agent re-learns "you are mid-session, you owe a clock-out" instead of starting blank. (1) `ledger-gates run exit` should verify the checklist (your codename has a `sessions.md` entry; `current.md` is cleared; your row is being removed) and fail loudly otherwise. (2) The pre-push hook could warn when you push with your own row still `Working` and no fresh session entry. (3) Next-session self-heal: a stale `Working` row (heartbeat expired) surfaced at check-in as "clock out this abandoned peer," so the office self-cleans even when a session vanishes. The leaving session can't be hard-gated, so the reliable guarantees are the resume reminder + the exit gate (while the agent is present) + next-session cleanup.
- **Status:** partly fixed in core **2.3.2**. The resume-proof reminder shipped — `ledger-guard remind` (the per-turn prompt hook) now surfaces your own still-open roster row and the Exit checklist + clock-out you owe, every turn including the first after a resume; a matching static line is in the `guard-reminder.md` floor. Live-verified (it fired for S021 and prompted the clock-out). **Still open:** the `ledger-gates run exit` checklist assertion and the pre-push warning (points 1–2 of the fix); the next-session self-heal (point 3) already exists as stale-row detection. Remaining scope the supervisor's call.
- **Addendum (Soren, S021) — points 1–2 fixed in core 2.3.3.** `ledger-guard exit-check` (run by `ledger-gates run exit`) now asserts the close-out: a `sessions.md` entry exists for your codename, `current.md` is not in-progress, and your roster row is not left `Working` (Done / Blocked / removed all pass — a parked Done row and a blocked hand-off are legitimate endings). It fails the exit gate when the close-out is incomplete and skips cleanly when it cannot tell who is leaving. `push-check` now warns (never blocks) when you push with your own row still `Working`. Live-verified: exit-check failed on *this* session while the S021 row was still Working, naming only the row. With the 2.3.2 resume reminder (point 0) and the stale-row self-heal (point 3), the exit flaw is now backed at every lever the ledger has. **Status: fixed in package 2.3.3** — the leaving agent cannot be hard-gated at "stop" by nature; reminder + exit gate (while present) + next-session cleanup are the guarantees.
