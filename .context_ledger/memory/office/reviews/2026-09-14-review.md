## What I found in the old README

The diagnosis in the critique is mostly right: the first screen was a
zone map and a Contents index — documentation for someone who already
cares, not a pitch for someone who doesn't. The product's own best
line ("Every session starts by reading… and ends by updating…") sat in
paragraph three. QUICKSTART.md already *is* the good walkthrough, so
the README was competing with it instead of handing off to it.

## Where I agreed — and where I didn't

Taken from the review: problem-first opening; the read/update rule
isolated as the memorable core; a two-session round-trip to *show* the
product instead of describing it; deep tables demoted below the fold.

Rejected, with reasons:

- **The tagline.** "Persistent memory for AI coding agents" sells half
  the product. A memory store without discipline rots into stale docs —
  the roster, claims, gates, and clocks-out are why the memory stays
  true, and they're the part competitors don't have. The shipped
  subtitle keeps both halves: *"…and the protocol that keeps it
  honest."*
- **The fabricated demo.** The review drafted imaginary console output.
  I kept to commands that actually exist (one bootstrap line, the one
  sentence that starts every session) and labeled the round-trip
  clearly as a scenario, not a transcript.
- **"Move the deep material out."** Right for the Contents table;
  wrong for "Working on this repo" — kickoff.md and the active workflow
  point at that section by title, and maintainer discipline
  (manifest-in-commit, suite, self-hosting) has nowhere else to live.
  It stays, verbatim, at the bottom.
- **The rename worry.** The name is crowded, yes — but the fix I chose
  is differentiation by structure, not a new name: a "What it is not"
  section that says plainly why this is not a chat-summarizer or a
  vector store (memory is markdown in git, diffable in a PR; no server;
  the protocol vendors itself into every clone).

Added on my own judgment (not in the review): the failure-logging
story as a differentiator — two friction logs feed releases, so the
protocol was shaped by the agents that used it; office rotation as
proof memory bounds itself; and the fleet sentence (it runs on real
projects plus its own repo) as the credibility line, without
stale-prone counts.
